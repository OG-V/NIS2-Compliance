Admin console accepts admin/admin

Failed check CHK-IDP-004: Default admin credentials are rejected

The law requires access control policies and, in the implementing regulation, that authentication credentials are changed initially, at predefined intervals and whenever compromise is suspected. The check logged in to the admin console with the username admin and the password admin and received HTTP status 200, whereas the expected result is that such a login is not accepted. A default credential that is publicly known gives anyone who reaches the console full administrative control of the system, so every other access control measure can be bypassed.

Remediation
  • Change the password of the 'admin' account so that the default admin/admin combination is no longer accepted, matching the expected result accepted: false.
  • Re-run the check to confirm the admin console rejects the default credentials.
  • Apply the credential-change rule described in point 11.6.2 to this account: change credentials initially, at predefined intervals, and upon suspicion of compromise.

Failed check CHK-SSH-001: SSH does not offer password authentication

Access control policies must ensure the strength of authentication is appropriate to the classification of the asset being accessed. The SSH server offers both password and publickey authentication, while the check expects password, keyboard-interactive and none not to be offered. Because password login remains available, remote attackers can attempt to guess credentials for shell access instead of being limited to key-based authentication.

  • Confirm the required users hold working public keys before the change, then re-run the check.

Failed check CHK-SSH-002: Direct root login over SSH is disabled

The implementing regulation requires administration privileges to be individualised and restricted to the highest extent possible. The scan found PermitRootLogin set to 'yes', while the expected setting is 'no'. Direct root login means administrative actions are performed through a shared, fully privileged account, so actions cannot be traced to an individual and one compromised credential grants complete control of the host.

  • Ensure administrators have individual accounts with the privilege escalation they need before applying the change.
  • Restart or reload the SSH service and re-run the check.

The server accepts TLSv1, TLSv1.1 and TLSv1.2, whereas the profile expects a minimum version of TLSv1.2.
