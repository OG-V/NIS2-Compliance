# Prompt v3: nested-list rule (2026-09-25)

**Problem (from [v2](2026-09-25-prompt-v2.md)):** provision 9.2 (cryptography policy)
produced 3 requirements in one run and 15 in another. That depended on whether the
twelve key-management sub-items (i)–(xii) inside point (c) became requirements of their
own. 9.2 is the only provision in the Annex with nested sub-items.

**Change:** one added rule. Roman-numeral sub-items stay within the requirement for
their lettered point.

**Runs:** one full gold-set run (`eval/runs/v3-a`) plus two runs of 9.2 alone
(`v3-92-b`, `v3-92-c`). Model `claude-opus-5`, prompt `2026-09-25.3`.

## Result: 9.2 is now stable

| Run | 9.2 requirements |
|---|---|
| v2-a | 15 |
| v2-b | 3 |
| v3-a | 3 |
| v3-92-b | 3 |
| v3-92-c | 3 |

All three v3 runs chose the same three clauses, (a), (b) and (c), with the same
testability labels (pairwise clause overlap 1.00). In every run the (c) requirement's
obligation names all twelve key-management methods.

**Caveat for reviewers:** the (c) quote is only the lead-in ("…including, where
appropriate, methods for the following:"). The twelve methods appear in the paraphrased
`obligation`, not in the verified quote, so the quote verifier cannot confirm that list.
A reviewer has to check it against the text.

Against v2-b, the provisions the rule doesn't touch came out almost identically: 19 of
20 had the same count, and clause overlap was 0.98. The remaining difference is 3.2.1,
which was already unstable under v2 (2 against 3 requirements, depending on whether
"respond accordingly" is split off). It has no nested list, so this rule was never
going to affect it.

## Status

Use prompt v3 for further extraction. The known remaining variation is:

- **3.2.1 granularity:** whether "detect" and "respond" are one obligation or two.
- **Testability labels on ambiguous points:** for example 6.6.1, documentary or technical.

Neither affects which clauses are found or whether quotes are correct.
