# Claude Opus 5 against Opus 5.5 (2026-09-25)

**Question:** can the LLM steps move from `claude-opus-5` to `claude-opus-5-5` without
losing quality?

**Setup:** the same prompt (extraction v3, narrative 2026-09-25.1), with only the model and
effort changed. Effort was set explicitly on both sides: Opus 5 at `high` (its default)
and Opus 5.5 at `medium` (its default, and Anthropic's suggested starting point). Setting
it explicitly keeps a model switch from silently changing effort as well.

- **Extraction:** gold set, `eval/runs/v3-a` (Opus 5) against `eval/runs/v3-opus55` (Opus 5.5)
- **Narrative:** the same live weak-lab scan, narrated once by each model

## Extraction

| Metric | Opus 5 / high | Opus 5.5 / medium |
|---|---|---|
| Requirements | 73 | 70 |
| Auto-rejected | 0 | 0 |
| Quote validity | 1.00 | 1.00 |
| Obligation recall | 1.00 | 1.00 |
| Granularity in gold range | 1.00 | 1.00 |
| Testability accuracy | 0.90 | 0.90 |
| Invented specificity | 0.00 | 0.00 |
| Vague stated values | 0.027 | **0.000** |

Between the models, 17 of 20 provisions have the same requirement count, and clause
overlap is 0.94. That's about the same as the variation between two Opus 5 runs (0.94),
so most of the difference is normal run-to-run variation. The three provisions that
changed were read one by one:

- **6.6.2, better.** The text says entities "*may* choose not to apply security patches".
  Opus 5 turned that permission into an obligation ("shall only choose not to…"), which
  was flagged as an interpretation in run 1. Opus 5.5 keeps only the actual obligation:
  document and substantiate the decision.
- **4.2.2, same content.** Opus 5.5 folds the lead-in ("lay down backup plans") into each
  of the six lettered items rather than making it a seventh requirement.
- **3.2.1, same content.** "Detect" and "respond" are one requirement instead of two, and
  the obligation text keeps both.

## Narrative

| | Opus 5 / high | Opus 5.5 / medium |
|---|---|---|
| Validator | accepted, attempt 2 | accepted, attempt 2 |
| Length (words) | 1,727 | 1,267 |
| Data field names used as words | 18 | 1 |

The known weakness from milestone 5, raw field names in text meant for managers, has
largely gone:

> **Opus 5:** "Central logs are configured with retention_period 1w, that is
> retention_days 7, while the profile expects min_retention_days of 90."
>
> **Opus 5.5:** "Central logs are deleted after 7 days, while the profile requires at
> least 90."

Both passed the same validator, so the gain in readability cost nothing in grounding.

## Decision

Both LLM steps now default to `claude-opus-5-5` at `medium` effort. It is at least as good
on every extraction metric, clearly better on narrative readability, and cheaper per token
($4/$20 against $5/$25 per million input/output tokens).

The 74 reviewed requirements extracted with Opus 5 keep that provenance in their
`extraction.model` field. They were approved as written and are not re-extracted.

## Stability (second Opus 5.5 run)

A second gold-set run (`eval/runs/v3-opus55-b`), with the same prompt, model and effort,
compared with the first:

| Run-to-run | Opus 5 / high (v2-a vs v2-b) | Opus 5.5 / medium (A vs B) |
|---|---|---|
| Provisions with the same requirement count | 18 / 20 | 19 / 20 |
| Mean clause overlap | 0.94 | 0.99 |
| Testability agreement on matched clauses | 0.95 | 0.99 |

The only structural difference between the two Opus 5.5 runs is 4.2.2: whether the
lead-in "lay down backup plans" is a requirement of its own (7) or is folded into the six
lettered items (6). There is also one differing testability label. Run B's gold-set
scores match run A's: quote validity and recall 1.00, granularity 1.00, testability
0.89, and no invented or vague values.

## Limits

Two runs per model show where variation happens, not a full distribution. The Opus 5
stability figures come from prompt v2 and the Opus 5.5 figures from prompt v3. The only
difference between those prompts is the nested-list rule, which affects only 9.2, and 9.2
agrees across both Opus 5.5 runs.
