## How to read these numbers

**Quote validity and recall are partly high by construction.** Gold keywords come from
the legal text, and a quote only passes if it is verbatim. So any quote that covers the
right clause also matches the keywords. Together the two metrics show that the model
found and cited every expected clause. They don't show that its plain-language
`obligation` is a faithful paraphrase. That judgement is what the human review is for.

**Invented specificity = 0 is the result that matters most.** Every trap provision kept
its open values open:

## Findings for the reviewer and the next prompt version

1. **Open values are written two ways.** For 3.2.5 the model used `entity_defined`, as
   instructed. For 11.6.2 and 6.6.1 it copied the vague phrase ("a predefined number")
   into `stated_value`. Both are faithful to the text, but they're inconsistent, and a
   downstream tool could mistake "a predefined number" for a stated value. Prompt v2
   should say that phrases like "predefined" or "reasonable" mean `stated_value: null`.
2. **7.3 was split into "review" and "update"** (the gold set expects 1). That's
   defensible but redundant. The model also silently repaired a grammatical slip in the
   law. The official text reads "…changes to operations or risks." with no verb, and the
   `obligation` adds "occur". The quote is still verbatim, so this is harmless, but the
   paraphrase isn't the text.
3. **6.6.2 turns a permission into a restriction.** The text says entities "*may* choose
   not to apply security patches when…". The extraction says "The entity shall *only*
   choose not to apply security patches where…". That's a reasonable legal reading, but
   it is an interpretation, and the reviewer should decide whether to keep it.
4. **Most testability mismatches are ambiguous, not wrong.** 6 of the 9 are points like
   "include restore procedures in the backup plan" (4.2.2), which can fairly be called
   documentary (the plan) or technical (the practice). The gold set labels testability
   per *provision*. For provisions that mix obligation types, it should label each
   obligation instead.

## Limits of this evaluation

- One run. Current models don't accept `temperature`, so a second run can differ.
  Stability has to be measured by repeating the run, not assumed.
- 20 of 159 provisions, chosen by topic rather than at random.
- A keyword match shows coverage, not correctness.
